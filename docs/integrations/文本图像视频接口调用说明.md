# 文本、语音、图像与视频接口调用说明

## 基础信息

所有接口使用统一的服务地址和 Bearer Token 鉴权。以下示例假设 Base URL 是站点根地址

```powershell
$serviceBaseUrl = "https://your-service.example.com"
$serviceApiKey = "<API_KEY>"
```

| 能力 | 方法 | 接口 |
| --- | --- | --- |
| 模型目录 | GET | `/v1/models` |
| 文本生成 | POST | `/v1/chat/completions` |
| 语音合成 | POST | `/v1/audio/speech` |
| 图像生成 | POST | `/v1/images/generations` |
| 图像编辑 | POST | `/v1/images/edits` |
| 视频创建 | POST | `/v1/videos` |
| 视频状态 | GET | `/v1/videos/{video_id}` |
| 网关媒体下载 | GET | `/v1/videos/{video_id}/content` |

## 模型目录

```powershell
curl.exe "$serviceBaseUrl/v1/models" `
  -H "Authorization: Bearer $serviceApiKey"
```

开启 `general_settings.model_list_generation_only: true` 后，目录只发布能够稳定归类为生成能力的模型。每个条目包含 `capability`，值为 `text`、`image`、`video` 或 `audio`

当前开发配置按模型名发布，不暴露 `toapis/`、`zexapi/` 等供应商前缀。每次生成请求必须显式传入 `model`，服务器不再使用默认模型匿名选型。

同一模型可包含多个内部 deployment。`image-2.5-flare` 和 `image-2.5-sunburst` 各连接对应 ToAPIs 普通版（order=1）与 VIP（order=2）；对外不单独发布 VIP 名称。普通版优先，明确的提交拒绝才回退到同系列 VIP。旧 `gpt-image-2` 模型池及各渠道的 image-2.0 部署停用；保留底层适配代码不等于启用路由。

路由还会在选择 deployment 前校验本次请求的图像参数。供应商接口对 `size`、`aspect_ratio`、`resolution`、`imageConfig`、参考图等参数的支持不同时，只会选择能够完整接受本次参数的 deployment；如果全部不支持，网关直接返回 400，不会把不兼容参数发到上游。

主要图像模型：

- `image-2.5-flare`
- `image-2.5-sunburst`
- `gemini-2.5-flash-image-preview`
- `gemini-3-pro-image-preview`
- `gemini-3.1-flash-image-preview`

主要视频模型系列：

- Omni：`gemini-omni-flash`、`gemini-omni-flash-preview-official`、`omni_flash-10s`、`omni_flash-10s-fl`
- Veo：`veo3.1-fast`、`veo3.1-quality`、`veo3.1-lite`、`Veo3.1-fast-official`、`Veo3.1-quality-official`、`Veo3.1-lite-official`，以及认证目录列出的 `veo_3_1-*` 固定规格型号
- Seedance：`seedance-2`、`seedance-2-fast`、`seedance-2-mini`、`seedance-2-5`
- 其他：`wan3.0-video`、`happyhorse-1.1`、`MiniMax-H3`
- Kling：`kling-v2-6`、`kling-v3`、`kling-3.0-turbo`、`kling-v3-omni`、`kling-video-o1`
- Grok：`grok-video-1.0`、`grok-video-1.5`

准确可用名称以认证后的 `/v1/models` 为准。

## 语音合成与音色管理

以下四个接口共用 LiteLLM Bearer Key 和模型访问权限。当前音色管理支持 MiniMax Speech 2.8 HD/Turbo；本地代码支持不等于运行环境已经部署、配置模型。

| 方法 | 接口 | 用途 |
| --- | --- | --- |
| POST | `/v1/audio/speech`（兼容 `/audio/speech`） | 文本与明确音色合成音频 |
| GET | `/v1/audio/voices?model=speech-2.8-hd` | 查询系统音色和调用方拥有的自定义音色 |
| POST | `/v1/audio/voices/design` | 根据声音描述生成音色 |
| POST | `/v1/audio/voices/clone` | 根据参考录音复刻音色 |

国内 deployment 配置：

```yaml
model_list:
  - model_name: speech-2.8-hd
    litellm_params:
      model: minimax/speech-2.8-hd
      api_base: https://api.minimax.cn
      api_key: os.environ/MINIMAX_API_KEY
      default_voice_id: female-yujie # 可选；省略 voice_id 时使用这个明确配置
```

管理员配置的默认音色必须是可用系统音色；自定义音色由请求明确指定，不能作为跨用户默认声音。没有默认配置且请求未指定音色时返回 400，不自动选择或生成声音。未配置 MiniMax Base URL 时保留国际站默认值。

### 合成请求

```json
{
  "model": "speech-2.8-hd",
  "text": "现在立刻放下，退到墙边！",
  "voice_setting": {
    "voice_id": "male-qn-badao",
    "emotion": "angry",
    "speed": 1,
    "pitch": 0,
    "vol": 1
  },
  "language_boost": "Chinese",
  "audio_setting": {"format": "mp3"}
}
```

- 必填 `model`、非空 `text`；MiniMax 同步合成少于 10000 个字符，原文不改写。
- `voice_setting.voice_id` 使用查询接口返回的系统或网关音色 ID。网关生成的 ID 与创建者、上游账号绑定，不能跨用户调用或自动换到其他上游账号。
- `emotion` 省略、null 或 `auto` 时不向 MiniMax 发送该字段，让上游自动判断。明确值只接受 `happy/sad/angry/fearful/disgusted/surprised/calm`。不解析中文别名或自然语言。
- `speed`：0.5–2；`pitch`：-12–12 的整数；`vol`：大于 0 且不超过 10。省略时采用上游默认值 1/0/1。越界值直接返回 400，不截断、不推断。
- `language_boost` 可选，仅接受上游枚举，省略时不传。`audio_setting` 默认 32kHz 单声道 MP3，也支持 WAV/FLAC/PCM；返回二进制，Content-Type 与实际输出对应。当前等待完整结果，不开放上游实时分片。
- `instructions`、`emotionIntensity` 不属于这两款模型的能力，非空指令或强度参数会被拒绝。需要根据声音描述创建音色时先调用 design。
- 旧字段 `input/voice/speed/response_format` 分别兼容 `text/voice_setting.voice_id/voice_setting.speed/audio_setting.format`。同时提供不同值返回 400。旧 OpenAI 音色名不再猜测为 MiniMax 音色。
- `extra_body` 兼容显式 MiniMax 原生参数。与顶层/嵌套参数冲突返回 400；不能覆盖 model、text、凭据、上游地址或返回类型。

### 音色设计

```http
POST /v1/audio/voices/design
Authorization: Bearer <LITELLM_KEY>
Idempotency-Key: project-character-voice-design-001
Content-Type: application/json
```

```json
{
  "model": "speech-2.8-hd",
  "prompt": "成年男性，声音低沉，吐字清楚，沉稳克制。",
  "preview_text": "先别慌，我来处理剩下的事。"
}
```

三个字段必填，试听文本最多 500 字符。`model` 用于选择部署及账号，不作为不存在的参数传给 MiniMax 音色设计接口。成功响应：

```json
{
  "voice_id": "voice_<网关生成的唯一ID>",
  "type": "designed",
  "model": "speech-2.8-hd",
  "status": "ready",
  "created_at": "<ISO 时间>",
  "preview_audio": {"content_type": "audio/mpeg", "data": "<Base64 音频>"}
}
```

### 声音复刻

```http
POST /v1/audio/voices/clone
Authorization: Bearer <LITELLM_KEY>
Idempotency-Key: project-character-voice-clone-001
Content-Type: multipart/form-data
```

表单字段：`model` 必填，`audio` 必填文件，`preview_text` 可选（1–1000 字符）。录音支持 MP3/M4A/WAV，最大 20 MiB；上游要求 10 秒至 5 分钟并校验音频内容。网关在同一部署完成文件上传和音色复刻，调用方不处理上游 file_id。

成功返回 `voice_id/type=cloned/model/status/created_at`；提供试听文本时另返回 `preview_audio.url`（上游试听链接，应及时保存）。不提供试听文本就不额外生成试听。设计和复刻的预览、首次正式使用音色可能产生上游费用，按 MiniMax 对应账号的账单计费。

### 归属、存储与失败处理

音色设计、复刻和查询需要 LiteLLM 数据库，使用现有 `LiteLLM_ManagedObjectTable` 的 `file_purpose=audio_voice` 记录归属、上游账号指纹、资源 ID 和状态，不存储上游密钥，不新增 schema。记录标记为已处理，避免被批量任务计费轮询器拾取。自定义音色按调用者身份和团队隔离；同一账号下的 HD/Turbo 可以复用。服务重启后仍可通过数据库查询。

创建前先持久化 `creating`；成功变为 `ready`。提交或保存结果不确定时保留 `unknown`（数据库写入失败时可能保留 creating），错误响应带原 voice_id。相同 Idempotency-Key 和同一请求返回已有成功结果；不同参数或未确定结果返回 409，不再次提交。没有幂等键的新请求会创建新的资源。未知结果需核查原音色，不应换键自动重试。查询不自动重新生成。

LiteLLM 模型目录的美元估算采用国际站公开价，不能当作国内人民币账单。国内实际计费字符以 MiniMax 响应/账单为准，当前未将音色管理费用自动并入 LiteLLM 的 token 费用统计。

### 星拓调用迁移

LiteLLM 协议的音频请求改用 text、voice_setting、audio_setting；情绪单独保存并发送枚举。旧中文自由情绪（如“坚定”）必须由用户重新选择，不能推断替换；历史任务不会因此重提。系统 OpenAI 别名需换为明确 MiniMax 音色或新创建的网关音色 ID。原有非 LiteLLM 渠道保留其旧协议。

官方参考：[合成](https://platform.minimax.cn/docs/api-reference/speech-t2a-http)、[音色设计](https://platform.minimax.cn/docs/api-reference/voice-design-design)、[复刻](https://platform.minimax.cn/docs/api-reference/voice-cloning-clone)、[音色列表](https://platform.minimax.cn/docs/api-reference/voice-management-get)。

## 图像生成

```powershell
curl.exe -X POST "$serviceBaseUrl/v1/images/generations" `
  -H "Authorization: Bearer $serviceApiKey" `
  -H "Content-Type: application/json" `
  --data-raw '{"model":"image-2.5-flare","prompt":"一只坐在窗边的橙猫，电影感光线","n":1,"size":"1:1","resolution":"1K"}'
```

从响应的所有 `data[].url` 或 `data[].b64_json` 读取结果，不要只保存第一项

图像尺寸参数：

| 模型 | 可用分辨率 | 说明 |
| --- | --- | --- |
| `image-2.5-flare`、`image-2.5-sunburst` | `1K`、`2K`、`4K` | 普通版传比例和分辨率；VIP 自动转像素尺寸并移除 resolution |
| `gemini-2.5-flash-image-preview` | `1K` | 固定 1K |
| `gemini-3-pro-image-preview` | `1K`、`2K`、`4K` | 按可用 deployment 路由 |
| `gemini-3.1-flash-image-preview` | `0.5K`、`1K`、`2K`、`4K` | `0.5K` 仅路由到明确支持它的 deployment |

可用顶层 `resolution`，也可用 `imageConfig.imageSize`；若两者同时出现，值必须一致。`size` 与 `aspect_ratio` 都表示画面比例，也不能互相冲突。不同供应商所需的比例、像素尺寸和字段位置由网关转换，调用方不要在 `extra_body` 中覆盖这些字段。

### Image 2.5 参考图修改及回退

这两个逻辑模型通过 `/v1/images/generations` 的 `image_url` 传入参考图，支持公开可访问的 HTTP(S) URL 和 `data:image/png;base64,...` 形式的 Base64 Data URL，可混合使用并保留顺序，返回标准 `data[].url`。不对它们开放 multipart `/v1/images/edits`。

ToAPIs 图片适配器会在选定部署后，将 Base64 参考图上传到同一部署的 `/v1/uploads/images`，再用返回的 URL 提交生成；已有 HTTP(S) URL 原样传递。同一次部署调用内重复的 Data URL 只上传一次；生成被明确拒绝后若按已有策略切换部署，使用该部署凭据重新上传，不跨部署共享上传缓存。支持 PNG、JPEG、WebP、GIF，每张解码后最大 10 MiB；不接受裸 Base64、文件路径或 `blob:` URL。格式校验无网络调用，所有参考图在上传前完成校验；上传失败时停止，不提交生成，也不自动重试或切换 VIP。此能力同样适用于 ToAPIs 适配器已有的其他参考图生成模型。

```json
{"model":"image-2.5-sunburst","prompt":"只把茶壶改为蓝色，保留其他物体","image_url":["https://cdn.example.com/teapot.png"],"size":"16:9","resolution":"2K","quality":"high","n":1}
```

普通版固定 high；VIP 支持 low/medium/high/xhigh/max，默认 high。可传 `background="transparent"`。例如 `16:9 + 2K` 在 VIP 中转为 `2048x1152`，参考图、提示词和透明背景在回退时保持不变。VIP 按实际 token 计费，不能把普通版每张价格当作 VIP 价格。

这两个组单独使用 deployment 级回退，不改变其他组的 provider 级回退：仅在普通版明确拒绝创建（400/401/403/404/422/429，或明确 no available channel 的 503）时尝试对应 VIP 一次。连接超时、一般 5xx、无效响应及取得任务 ID 后的失败仍禁止重新创建，避免重复扣费。普通版进入冷却或被管理员暂停时可选用 VIP；普通版恢复后优先回到 order=1。内容策略拒绝不自动回退。

## 旧 Image 2.0 图像编辑契约（已停用路由）

重复使用同名 `image` 字段上传多张参考图，不要手工设置 multipart boundary

```powershell
curl.exe -X POST "$serviceBaseUrl/v1/images/edits" `
  -H "Authorization: Bearer $serviceApiKey" `
  -F "model=gpt-image-2" `
  -F "prompt=保持主体，只把背景改为夜景" `
  -F "image=@reference-1.png" `
  -F "image=@reference-2.png" `
  -F "aspect_ratio=16:9" `
  -F "resolution=2K"
```

ZexAPI 编辑支持与生成一致的比例、K 档转换：`aspect_ratio=16:9`、`resolution=2K` 会转换为 `model=gpt-image2`、`size=2560x1440`，出站不保留 `aspect_ratio/resolution`。规格来自[章鱼哥接口文档](https://6l0ket291i.apifox.cn/447357296e0)。`image2` 只支持 1K，Router 会在 2K/4K 编辑请求选路前排除它，即使开启 `drop_params` 也不会把 K 档静默丢掉。

如同时传入精确像素 `size`，它必须与比例、K 档一致；冲突或不支持的规格会在上游调用前拒绝。客户端选择自动时省略对应字段，不发送字符串 `auto`；没有尺寸参数的编辑请求不会被补成固定像素。原图、多图、mask、透明背景与响应格式继续保留各自编辑语义。本转换不会启用被管理员禁用的部署，也不会替供应商补充未支持的编辑能力。

## 旧 ZexAPI 异步图片型号（已停用路由，仅保留适配参考）

ZexAPI 的 `gpt-image-2`、`gpt-image-2-2K`、`gpt-image-2-4K` 使用独立的异步图片契约，不能替换同步 `gpt-image2` 的名称后继续直调同一个上游接口。LiteLLM 已支持将公开 `/v1/images/generations` 和普通无 mask 的 `/v1/images/edits` 转成上游 `POST /v1/videos`，内部查询 `GET /v1/videos/{task_id}`，完成后统一返回 `data[].url`。

三个物理型号分别匹配 1K、2K、4K。可配置在同一逻辑模型池，Router 根据本次 `resolution` 筛选匹配部署；不在单个 deployment 内静默更换收费型号：

```yaml
model_list:
  - model_name: gpt-image-2
    litellm_params:
      model: zexapi/gpt-image-2
      api_key: os.environ/ZEXAPI_API_KEY
  - model_name: gpt-image-2
    litellm_params:
      model: zexapi/gpt-image-2-2K
      api_key: os.environ/ZEXAPI_API_KEY
  - model_name: gpt-image-2
    litellm_params:
      model: zexapi/gpt-image-2-4K
      api_key: os.environ/ZEXAPI_API_KEY
```

- `aspect_ratio=16:9 + resolution=2K` 选中 `gpt-image-2-2K`，上游只传 `model/prompt/aspect_ratio` 以及可选 `images`。
- 普通生成通过 `image_url` 传 URL/Data URL 参考图；编辑接口的上传文件会转为 Data URL。每次最多 8 张参考图，依据供应商文档；不在本地裁切或缩放。
- 自动或缺失比例不补成 `1:1`；档位由选中的物理型号确定。显式像素 `size` 必须符合该档规格；若同时提供固定比例，两者必须一致，内部只向上游发送 `size`。
- 目前支持 URL 结果和单张输出；`mask`、`input_fidelity`、透明背景、`quality`、`imageConfig`、不匹配的 K 档会在提交前拒绝，即使设置 `drop_params=true` 也不会丢掉这些语义继续生成。不支持通过 `extra_body` 覆盖这份契约。
- 提交后只查询原任务。轮询间隔为文档建议的 5 秒，总预算使用本次请求的 `timeout`；提交结果未知及拿到 ID 后的错误保留 submission provenance，禁止 Router 重试或 fallback 再次创建。成功结果的隐藏 metadata 和受理后异常保留原任务 ID，查询响应中的通用 `model=gpt-image-2` 不覆盖原始档位。
- 公开图片 API 仍等待最终结果；本次没有新增跨请求持久化任务查询 API。配置和代码发布前不会改变生产模型池。同步 `image2/gpt-image2` 继续使用原契约。

依据：[异步图片创建](https://6l0ket291i.apifox.cn/447634846e0)、[任务查询](https://6l0ket291i.apifox.cn/455245131e0)。

## 视频生成

生成、编辑、延长共用 JSON `POST /v1/videos`，以及原有任务查询和下载接口。可选顶层 `operation` 为 `generate`、`edit`、`extend`；省略或 null 按生成处理，不能放进 `extra_body`。

Seedance 2.5 编辑示例：

```json
{
  "model": "seedance-2-5",
  "operation": "edit",
  "prompt": "将视频1的背景改为海边日落，保留人物动作",
  "resolution": "720p",
  "references": [
    {"type": "video", "role": "reference", "url": "https://cdn.example.com/source.mp4"}
  ]
}
```

延长使用同一结构，改成 `operation=extend`、相应延长提示词，并可加 `seconds="15"` 指定延长后的输出总时长为 15 秒（不是新增 15 秒）。编辑和延长至少需要一条视频，均须省略 `aspect_ratio`，由源素材决定比例。编辑的 `seconds` 只能省略或为 `"-1"`；延长可省略、为 `"-1"` 或 `"4"`–`"30"`。省略时由模型决定时长。非法组合在提交前返回 400，不会静默改成普通生成。

HappyHorse / Gemini Omni Official 的统一视频编辑请求也须显式传 `operation="edit"`；不传操作不再自动编辑。不支持对应操作的 deployment 不参与路由选择，其他模型的显式编辑/延长能力以其已实现的适配为准。ToAPIs 原生 `video_operation`、`duration`、`action` 等由网关转换，不与上述统一字段混传。

星拓造镜新增显式 `LiteLLM` 协议时，使用 JSON `POST /v1/videos`：

```json
{
  "model": "seedance-2",
  "prompt": "保持人物形象，参考视频运镜和音频节奏",
  "seconds": "5",
  "resolution": "1080p",
  "aspect_ratio": "16:9",
  "references": [
    {"type": "image", "role": "reference", "url": "https://cdn.example.com/person.png"},
    {"type": "video", "role": "reference", "url": "https://cdn.example.com/motion.mp4"},
    {"type": "audio", "role": "reference", "url": "https://cdn.example.com/rhythm.mp3"}
  ]
}
```

`resolution` 只接受 `480p/720p/1080p/2K/4K`；`aspect_ratio` 只接受比例，智能选择时省略对应字段。`references` 保留全部素材和顺序，图片角色可以是 `reference/first_frame/last_frame`，视频和音频仅可用 `reference`。尾帧需要首帧且不能是同一图片。不要同时发送 `size/width/height/input_reference`，也不要用原生参数覆盖这些字段。

网关按真实供应商能力校验并转换，UnsupportedParams/无兼容 deployment 返回 400，不能把不支持档位静默丢弃。具体模型范围和文档依据见 [视频映射契约](../../litellm/llms/toapis/videos/videos-contract.md)。后续仍使用原任务 ID 查询和下载，不重复创建。普通 OpenAI 的原 multipart 契约如下，不能据此宣称所有 OpenAI 渠道支持上述扩展。

纯文生视频不发送 `input_reference`

```powershell
curl.exe -X POST "$serviceBaseUrl/v1/videos" `
  -H "Authorization: Bearer $serviceApiKey" `
  -F "model=seedance-2" `
  -F "prompt=日落时分，海浪缓慢拍打沙滩，电影感镜头" `
  -F "seconds=12" `
  -F "size=1920x1080"
```

图生视频增加一份真实图片文件

```powershell
curl.exe -X POST "$serviceBaseUrl/v1/videos" `
  -H "Authorization: Bearer $serviceApiKey" `
  -F "model=seedance-2" `
  -F "prompt=镜头缓慢靠近主体" `
  -F "seconds=12" `
  -F "size=1920x1080" `
  -F "input_reference=@reference.png"
```

创建响应中的 `id` 用于轮询

```powershell
$videoId = "video_xxx"
curl.exe "$serviceBaseUrl/v1/videos/$videoId" `
  -H "Authorization: Bearer $serviceApiKey"
```

完成状态会返回可下载的 `output_url`

- 绝对 URL：直接下载该地址
- `/v1/videos/{id}/content`：携带网关 Bearer Token 下载，响应直接是媒体字节且不会重定向
