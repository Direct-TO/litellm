# Seedance 2.5 单入口参考视频意图识别

下游继续调用 `POST /v1/videos`，使用同一个公共模型名，传提示词和 `references`。
无需增加编辑/延长选项。服务端在视频创建请求通过现有前置检查后、路由前调用一个文本模型识别意图。
本功能不处理任务查询，不在异步失败后修改参数或重新提交。

## 配置

```yaml
general_settings:
  video_reference_intent:
    classifier_model: deepseek-chat
    models: [seedance-2-5]
    timeout: 20
```

`classifier_model` 是 Router 中已经配置好的文本模型组名，不是固定供应商。
本地 dev_config 示例选择其中配置的 `deepseek-chat`；生产应以管理接口中实际启用的文本模型组为准，可换成其他支持 JSON 输出的聊天模型组。
不新增下游视频模型名、不复制密钥。移除 `video_reference_intent` 即关闭功能。
启用后每个匹配请求会增加一次内部文本模型调用及相应耗时、费用。
生产使用数据库中的动态配置时，也需设置同名 general_settings；仅修改本地文件不会更新服务器。

## 范围与参数

仅处理配置 `models` 中含至少一个标准视频参考、`operation` 缺省或为 `generate` 的请求。
明确传入的 `edit`/`extend` 保持旧接口行为。其他模型、无视频参考请求和任务查询不调用分类器。

| 识别意图 | 实际渠道 | 实际操作 | 时长与比例 |
| --- | --- | --- | --- |
| 普通生成 | 原有合适渠道 | generate | 保留原参数 |
| 修改原视频 | ToAPIs Seedance 2.5 | edit | seconds=-1，移除固定比例，适配器填 adaptive |
| 从原片结尾续接 | ToAPIs Seedance 2.5 | generate | 生成新增片段，保留 seconds；提示词明确新增秒数时采用该值；保留比例 |

**续接不累加源视频时长，也不调用专用 `video_operation=extend`。**
它沿用本项目已复现的“参考生成 + 续接提示词”调用方式；原片 8 秒、新增 4 秒，仍传 4 秒。
专用 extend 接口仍有独立的参数契约，不修改它的既有行为。
这里不承诺供应商内部选择了专用延长类型，也不保证所有提示词都能成功续接。

LLM 仅返回结构化意图、目标视频编号和提示词中明确给出的时长。代码负责验证和参数转换。
分类器不接收素材 URL、文件字节或视频画面；不改写实际生成提示词、不重新排序素材。
多视频编号按 references 中视频出现的顺序从 1 开始；目标必须在范围内。
用户同时要求修改与延长、目标不明确、请求“延长到总长”而未提供新增时长，均在提交前报错。
输入的新增秒数允许 4–30 或 -1；不裁剪、不拆分、不计算原片加新增时长。

## 提交与错误

- 分类器超时、输出不合法、识别模型未配置：返回错误，不提交视频任务。
- 没有可用 ToAPIs 部署时：特殊意图请求失败，不能降级到其他渠道。
- 自动识别的请求禁止 Router 重试、同组换部署及跨组 fallback；同时跳过现有私有人像恢复中的再次提交。
- 上游已接受的任务继续使用原有视频 ID 编码和查询流程，查询到失败即返回失败。
- 请求内的渠道凭据覆盖、user_config 和冲突原生媒体参数不适用于此入口。

## 日志与验证

原始提示词/请求沿用现有日志策略；识别审计记录放在
`metadata.spend_logs_metadata.seedance_video_intent`，包括分类模型、提示词哈希、原始参数、分类结果、有效参数和渠道限制。
分类调用通过 `parent_video_call_id` 关联原请求并继承用户归属字段；上游任务 ID 和实际 deployment 沿用现有日志。

自动化测试使用模拟文本/视频上游，覆盖真实 Router 和适配器的数据流、普通生成分流、错误终止、禁止重试与日志持久化字段。
不以模拟分类结果证明真实模型的分类准确率；部署后的真实端到端验收需要另行执行。
